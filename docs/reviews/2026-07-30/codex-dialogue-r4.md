2. **Plan placement and drift checking**

   No XDK task should enter the roadmap. Stage 4a should make the raw Valibot schemas the sole X wire-contract source and derive application types from them. `satisfies` remains appropriate for handler response values; captured raw fixtures plus parser tests provide the meaningful drift guard. The `loginUrl` failure class is entirely internal and would not have been caught by XDK types.

   If types-only adoption is nevertheless mandated later, it belongs in Stage 4a after normalization exists, pinned exactly, with an unexecuted `xdk-contract.typecheck.ts`. Use type-level one-way assignability assertions from a camelCase normalized X DTO to the corresponding `Schemas.*` type—not `satisfies`, and not the raw schema input. That would catch some field-type changes, but not wire drift comprehensively because the official types are permissive and post-transformation.

Runtime XDK adoption should be reconsidered only after those layers exist and the SDK offers injectable transport, explicit credential selection, trustworthy retry disabling, and either raw wire types or runtime schemas. The plan remains converged.
