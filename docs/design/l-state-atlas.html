x-threaded — State Atlas

This is the whole inventory of the avatar-graph, drawn. Every element the tree can put on screen, in every state it can be in, has exactly one exhibit below — so that reviewing this design is verification rather than discovery. Nothing here is a default that nobody looked at, because there is nothing here that has not been drawn. The grammar and the CSS are K-avatar-graph's, unchanged; this page only exercises them over the full element × state list in avatar-graph-coherence-spec.md, whose row numbers each caption cites.

Held-open states. A hover preview or a focus ring that only exists under a live pointer cannot be reviewed in a screenshot, so where an exhibit shows one it is pinned open with .is-hover or .is-focus and the caption says so. Everything else is at rest. Reading the marks: the line bends only where the conversation branches — a rounded elbow is a fork, a straight line is a continuation, a dashed bead is a post we never got, a ⊖ / ⊕ disc on the line is a fold station — open, then closed — with the ghost chip standing where the first hidden avatar would have, an accent ring is unread, an accent bar and warm bed are the keyboard cursor. Reading a preview: per ruling (e-settled) the line you are pointing at brightens — the handle's own ink, the block's vertical run, and the first-level elbows that reach its direct children's avatars — and nothing else on the page changes at all. No surface is tinted, nested marks and children's own drops keep their ink, bystander stubs keep theirs, and no avatar or ring is involved; the fold's own ⊖ brightens with the line, because it is made of the same ink. The line is the handle (h-amend) and, since ruling (s), the mark, the line and the ghost chip are one control in three shapes — press any of them and the same fold runs. Where an exhibit draws a state rather than running a fold, its caption says so. The three findings this atlas reported upstream are fixed in this round: K's .is-root descendant selectors, ruling (o)'s zero motion, and the open question about the direct arm's fold handle — which (s-amend) closed by retiring ruling (j) outright.

Depth floor — a PARKED proposal, not v1

A11

Mobile — 390px, the compressed tokens

Row 30. The same drawing at a 390px width, with the narrow tokens applied as a class so the strip can be shown inside a wide page: avatar 28px, fork 1.95rem, lane gap .55rem, bed lead 1.5rem. The fork step is the one number (s-amend) moved. Spec row 30 said 1.6rem; at that step the take-off arm's straight span — the run between the departure curve and the corner, --fork + --line-w − 2 × --elbow-r — measures 7.6px, and an 11px disc centred on it would sit half on the curve, which the ruling forbids. The ruling anticipates exactly that (“or the narrow fork step grows to fit”), so the step grew: 1.95rem gives 13.2px of straight ink, and it is the same number the wide clamp now floors at, so the drawing has one fork minimum everywhere. Nothing else about the grammar changes — the elbow still lands on the avatar's 9 o'clock, the bed still reaches past the lane, the fold station still sits at --own-t on the owner's line with its ghost in the first hidden avatar's seat — because every coordinate is derived from those numbers and none is written by hand. One note for the implementation, measured rather than assumed. An alias like --lane: var(--avatar) resolves against the element's own cascaded properties, so it does follow a re-declaration on the same element: K's 34rem block overrides --avatar at :root and --lane there computes to 28px unaided. But the alias then inherits already substituted, so a descendant scope that re-declares only the base token gets the ancestor's flat value — and this strip is exactly that descendant. Set --avatar here alone and the lane stays 32px while every mark aims 2px wide of the bead; the same trap once caught --arm-t, which read --avatar too — that token went with ruling (j), and the mid-arm station that replaced it is the mark box's own centre, so there is nothing left there to leave stale. A12

Final segment with replies — the thread opens out at its end

Rows 2 and 4b, ruling (i-amend). The bundle exists where the thread continues. A mid-thread segment's replies go onto a take-off so that the next trunk bead is unmistakable — that is bead 1 below. The final segment has no continuation to protect, so it needs no bundle: its replies attach directly to its own line, ╰ ends the line, and the thread visibly opens out into its discussion at its end (bead 3). What ruling (i) forbids is unchanged and still holds — a terminal ╰━━╮ would say “the trunk turns into this block”, which is exactly the thread-or-reply confusion the bundle was invented to kill. The lone root (A2) is this same rule in its length-1 case: one segment, no continuation, replies straight off the line. The final segment's fold station is on its own drop, not on a tee, because that is where its foldable content attaches — ruling (h) applied without amendment, and ruling (s) putting the ⊖ there.
